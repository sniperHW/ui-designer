# 卡牌页素材质量标准 v1

## 适用范围

所有导入 `.uiw` 的 PNG：背景、资源条、按钮、Tab、金属容器、卡框、角标、卡面窗、进度条、图标、升级标和底部导航状态皮肤。该标准同样适用于既有素材的返工，不因“先前已通过”而豁免。

## 必经工序

| 工序 | 交付物 | 不通过示例 |
|---|---|---|
| 锚点测量 | 节点尺寸、透明轮廓、运行时区域 | 以视觉猜测裁切；文字槽被烘焙进 PNG |
| 无字结构源 | 独立 PNG 或锚点裁定区域 | 带入周边背景、其他控件或动态信息 |
| ImageGen 精修（按需） | 同结构、无字、清洁边缘候选图 | 锯齿、压缩噪点、断边、不自然渐变、非对称金属框 |
| 真实透明化 | 带 alpha 的规范 PNG | 白底、棋盘格被烘焙、黑边、灰边、预乘色残留 |
| 边缘与渐变修复 | 轮廓闭合、连续抗锯齿的规范 PNG | 外框裁断、上下不对称、边缘发脏、亮暗突变 |
| 尺寸规范化 | 与节点设计像素一致的 PNG | 使用大图直接压缩进 UIW；边缘被缩放裁断 |
| 工具装配验收 | 真实交互 `.uiw` 截图 | 单图好看但在真实背景、缩放或交互状态下出现瑕疵 |

## 强制视觉门禁

- 透明素材边缘必须在页面真实背景上观察；透明网格预览不能作为验收依据。
- 金属闭合框至少检查上、下、左、右四边与四个角；若设计应对称，则边缘的视觉重量、亮度与切角必须对称。
- 金属渐变必须在 100% 和页面实际缩放下连续，不允许出现灰蓝通道残留、黑色画布晕边或单像素锯齿。
- 任何动态文字、数字、进度或选中态都必须以 `.uiw` 节点运行，不得为追求相似度烘焙进素材。
- 若锚点裁定区域遗留动态文字槽、空框或数值底座，必须以相邻同材质表面的逐行采样重建其渐变与 alpha；禁止用纯色块遮盖，也不得把改变尺寸、外轮廓或透明画布的生图候选直接替换进项目。
- 尺寸、透明、轮廓通过脚本检查后，仍必须由实际装配截图进行人工视觉确认。
- 卡面立绘必须先按卡面窗采用 `cover` 裁切到节点的精确设计像素；如原图含半透明像素，必须先合成稀有度匹配的卡面底衬，最终资源 alpha 必须为 `255`。不得将带透明边缘或小于窗口的原图直接绑定到卡面节点。
- 卡牌层级必须为“卡面图片 → 卡框 → 种族底座 → 种族图标 → 动态等级/进度/升级标”。种族徽章与卡面窗有交叠时，徽章必须完整显示在卡面之上。
- 对生图框体，除透明窗外还必须检查内侧分隔带是否残留不透明的白色/棋盘展示底；此类像素仅可在锚点标注的结构保留区通过定向重着色清除，不能以全图去白破坏金属高光。
- 带切角、圆角或异形外轮廓的框体必须建立最终设计像素的真实 alpha 轮廓遮罩；四角不得保留生图展示底色。遮罩必须使用抗锯齿边缘，并在页面真实背景上验收。
- 若轮廓外仍有与页面无关的近黑像素，必须执行“外沿连通深色哑光清除”：仅清除从画布外侧可穿透到的近黑展示底，并保留由金属边界隔开的深蓝内衬。不得把黑色展示底误当成阴影保留。
- 当金属边缘本身含深蓝暗部时，外沿门禁必须同时声明已测量的透明边界带；该带内任何不透明像素均构建失败。不得以放宽近黑阈值或像素预算的方式保留画布黑底。
- 任何既有素材只要被重新装配或局部修改，均必须重新经过全量质量门禁；不得因“本次没有修改边缘”跳过。异形素材的构建清单必须声明 `quality_gate.edge_dark_matte`，构建脚本会检测从画布外侧可连通的可见近黑像素；阈值必须按该素材已确认的深蓝内衬和外缘线宽测量，不能穿透真实金属结构；超过阈值即构建失败，不得进入 `.uiw`。
- 无字框体还必须扫描孤立的高亮/近白残留像素；未被锚点标注为金属高光或功能图标的残留，一律先定位、再用限定区域转真实 alpha，不能作为“可接受的噪点”进入装配。
- 一个语义元素只能拥有一个视觉底座：例如种族徽章的底座属于种族节点，卡框不得在同一位置重复绘制装饰座。默认无状态的功能标识必须以节点隐藏实现，不得用白点、空框或空文本占位。
- 独立图标必须是带真实 alpha 的无底图 PNG，并直接叠加到所属容器的完整内衬上。容器底板不得为了覆盖旧烘焙图标而补画纯色方块、圆形、六边形、徽章座或其他局部底座；应改用本身不含该图标槽的无字完整底板。图标与容器的边缘、阴影和金属结构分别只由各自的语义层负责。
- 复合状态条必须以装配合同拆分：容器素材只承担完整框体、内衬与固定分隔线；每个可替换的功能图标均为独立的透明素材和 `.uiw` 节点；文字、数值和进度均为运行时节点。不得把容器与任一功能图标烘焙为同一张 PNG。
- 同一语义图标在筛选、卡牌角标、战力统计等位置出现时，必须复用同一原始轮廓资源；不同上下文只允许通过参数化的尺寸、单色化和位置适配，不能另行重画造成识别不一致。任何单色化仍须保留源素材的真实 alpha，禁止在图标下新增色块或底板。
- 可复用的闭合框体必须只使用一份完整、上下左右四边闭合的状态皮肤；不得把带“相邻控件分隔线”的横向切片当作独立按钮重复平铺。多个完整边框并列时，装配清单必须显式声明各项宽度、固定间距与总宽度守恒；相邻边框重叠、双线、最后一项裁断或溢出，任一项均为构建失败。

## 固化工具责任

- `build_chrome_family.py`：锚点结构提取、透明轮廓、文字区清除、边缘深色画布清除、对称边缘重建。
- `build_background_family.py`：ImageGen/外部候选图的展示底转真实 alpha、外沿连通深色哑光清除、内容裁边、真实尺寸规范化、边缘渐变重建，并执行清单声明的外沿深色哑光质量门禁。
- `build_background_family.py` 的 `recolor_visible_to_color`：仅改变复用透明图标的可见像素颜色并原样保留 alpha，用于统一战力统计等上下文的扁平白色表达。
- `build_chrome_family.py` 的 `flat_icon`：按同类参数生成独立的抗锯齿、无底图、真实 alpha 的简约符号；不得以截图裁块替代。
- `build_background_family.py` 的 `surface_inpaint_rects`：按同类材质的左右邻域逐行重建误烘焙的运行时槽位；同时可通过 `forbid_warm_metal_regions` 门禁，阻止金色空框或数值槽回流到素材库。
- `build_card_family.py`：卡面框体/进度组件与角色立绘的统一构建；负责 `cover` 覆盖、底衬合成和不透明度门禁。
- `assemble_uiw_preview.py`：只负责绑定规范素材与保留真实交互；独立图标只能以透明图层叠加到完整容器底板，且不得通过改变节点尺寸、添加补色底座或隐藏动态节点迁就素材。
- `compare_anchor.py`：用于定位比例和色彩差异；最终是否通过以真实装配视觉验收为准。

## 当前执行约定

后续每一类素材先按本标准完成，才可进入下一类。最终整页阶段会重新复查前述所有已冻结素材；凡发现黑边、灰边、锯齿、透明通道残留、结构断边或缩放失真，回到该素材的精修关处理。
